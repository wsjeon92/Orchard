# Orchard

생각을 심고, 돌보고, 거두는 곳. 설익은 연구 아이디어를 **너비**와 **깊이**
두 축으로 디벨롭해 착수할 수 있는 형태까지 끌고 가는 그래프 도구다.
서버도 계정도 없이 브라우저 안에서만 돌아가고, 작업은 자동 저장된다.

- **너비** — 키워드끼리 잇고, 그 교차에 이름을 붙여 새 키워드로 승격한다.
  단백질 × 디자인 → `단백질 디자인`
- **깊이** — 아이디어 하나를 질문 → 가설 → 접근 → 검증 → 리스크로 전개한다.

조사와 판단은 사용자가 한다. AI 호출은 들어 있지 않다.

---

## 개발

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm run build      # 타입 검사 + 빌드 → dist/index.html
npm run preview    # 빌드 결과 미리보기
npm run typecheck  # 타입만 검사
```

이 네 줄은 Windows·macOS·Linux 어디서나 같다. 셸에 따라 달라지는 건 아래
테스트 실행 부분뿐이다.

빌드 결과는 **HTML 한 파일**(`dist/index.html`)이다. 정적 호스팅에 그대로 올라가고,
내려받아 더블클릭해도 열린다.

### WSL 에서

Windows 에서는 WSL(Ubuntu)을 쓰는 쪽이 편하다. 두 가지만 지키면 된다.

**1. 프로젝트를 리눅스 파일시스템 안에 둘 것.** `/mnt/c/...` 아래에 두면
npm 설치와 빌드가 몇 배 느려지고, 개발 서버의 파일 변경 감지가 자주 실패한다.
`~/` 아래로 옮긴다.

```bash
# WSL 터미널에서
cd ~
git clone https://github.com/wsjeon92/Orchard.git
cd Orchard
```

**2. Node 를 WSL 안에 설치할 것.** Windows 쪽 Node 가 PATH 에 잡혀 있어도
그걸 쓰면 안 된다 (`which node` 가 `/mnt/c/...` 를 가리키면 그 경우다).

```bash
# nvm 으로 설치 (권장)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
exec $SHELL
nvm install 20

node -v && which node     # /home/<사용자>/.nvm/... 이어야 한다
```

그다음은 똑같다.

```bash
npm install
npm run dev
```

개발 서버를 띄우면 **Windows 쪽 브라우저에서 `http://localhost:5173`** 으로 그냥
열린다. WSL2 가 localhost 를 넘겨준다. 안 열리면 `npm run dev -- --host` 로 띄우고
WSL 의 IP(`hostname -I`)로 접속한다.

빌드한 파일을 Windows 탐색기로 꺼내려면 WSL 경로가 그대로 보인다:
`\\wsl$\Ubuntu\home\<사용자>\Orchard\dist\index.html`

### PowerShell 에서

WSL 없이 PowerShell 로도 된다. `npm` 명령은 그대로고, 테스트도 `python test/run_all.py`
한 줄이라 셸 문법을 탈 일이 없다. 다만 Windows 에서 Python 명령은 보통 `python`
또는 `py` 다 (`python3` 아님).

## 배포

세 가지 중 편한 쪽을 쓰면 된다. 어느 쪽이든 빌드 명령은 `npm run build`,
배포할 폴더는 `dist` 다.

**GitHub Pages** — `.github/workflows/deploy.yml` 이 들어 있다.
저장소 Settings → Pages → Source 를 **GitHub Actions** 로 바꾸고 `main` 에 푸시하면 끝.
주소는 `https://<사용자>.github.io/orchard/` 가 된다.
(`vite.config.ts` 의 `base: "./"` 덕에 하위 경로에서도 동작한다.)

**Netlify** — 저장소를 연결하면 `netlify.toml` 을 읽어 알아서 빌드한다.

**Vercel** — 저장소를 연결하면 `vercel.json` 을 읽는다.

**그냥 파일로** — `dist/index.html` 하나만 어디든 올리거나 그대로 열어도 된다.

| 파일 | 하는 일 |
| --- | --- |

| `kinds.ts` | 노드 종류별 이름·색·모양, 깊이 항목 순서, 검색 사이트 |

| `graph.ts` | 그래프 조회와 변경 (이웃, 집중 범위, 접기, 노드·엣지 추가/삭제, 승격, 그룹, 하위 키워드) |
| `labels.ts` | 엣지 이름 겹침 회피 |

| `anim.ts` | 위치 보간 애니메이션 |
| `panel.ts` | 오른쪽 사이드 패널 |

| `minimap.ts` | 미니맵 |
| `history.ts` | 실행 취소 / 다시 실행 |
| `modals.ts` | 입력창, 내보내기·가져오기, 저장본 목록, 보기 설정 |

| `main.ts` | 배선과 부트 |

테스트 쪽 `test/conftest_paths.py` 는 빌드 산출물·스크린샷 경로와 브라우저
실행을 한곳에서 처리한다. 절대 경로를 박아두면 만든 사람 컴퓨터에서만 돌아간다.

### 알아둘 만한 설계 결정

**애니메이션은 CSS 가 아니라 JS 보간이다.** SVG `<line>` 의 좌표는 CSS 트랜지션
대상이 아니라서, CSS 로 노드만 움직이면 선이 따라오지 못하고 튄다. 그래서 표시
좌표(`_rx`, `_ry`)를 JS 에서 목표 좌표로 수렴시키고 노드·선·라벨을 같은 프레임에
함께 그린다 (`anim.ts`, `render.ts#paint`).

**엣지 이름 회피는 목표 좌표 기준으로 푼다.** 애니메이션 중간 위치로 풀면 움직임이
멈춘 뒤 그 해답이 맞지 않아 결국 겹친 채로 남는다 (`labels.ts`).

**저장 키는 절대 바꾸지 않는다.** 구조가 바뀌면 `normalize()` 로 올린다. 키를 바꾸면
사용자 데이터가 그냥 사라진다. 예전 키들은 `LS_OLD` 에서 한 번만 끌어온다.
프로젝트 이름이 Orchard 로 바뀐 뒤에도 `kwgraph.` 접두어를 그대로 쓰는 이유가 이것이다.

**실행 취소는 `save()` 에 걸려 있다.** 제목·메모 입력은 전체 렌더를 거치지 않고
`save()` 만 부르기 때문에, 거기 두어야 빠짐이 없다 (`state.ts`, `history.ts`).

## 테스트

Playwright 로 빌드 결과(`dist/index.html`)를 직접 띄워 검증한다. 헤드리스라
GUI 가 없는 WSL 에서도 그대로 돌아간다.

준비 (한 번만):

```bash
pip install playwright
playwright install chromium          # WSL·리눅스면: playwright install --with-deps chromium
```

실행 — 셸 종류와 무관하게 한 줄이다:

```bash
npm run build
python test/run_all.py               # WSL·macOS 면 python3
```

개별 실행:

```bash
python test/smoke7.py
```

경로는 전부 스크립트 위치 기준으로 잡히므로 어느 디렉터리에서 실행해도 된다.
설치된 Chrome 이 있으면 그걸 쓰고 없으면 Playwright 가 받아 둔 Chromium 으로
떨어진다. 특정 브라우저를 쓰려면 `ORCHARD_CHROME` 에 실행 파일 경로를 넣는다.

| 파일 | 다루는 것 |
| --- | --- |
| `smoke.py` | 예전 저장 키 승계, 하이퍼엣지, 저장본 |
| `smoke2.py` | 하위 키워드 계층, 순환 차단 |
| `smoke5.py` / `smoke6.py` | 그룹 — 드롭다운 추가, 직접 입력 |
| `smoke7.py` | 접기, 미니맵, 집중 깊이, 검색, 텍스트 페이드, 연결 수 크기 |
| `smoke8.py` | 실행 취소 / 다시 실행 |
| `smoke9.py` / `smoke11.py` / `smoke12.py` | 엣지 이름 겹침 회피 |
| `smoke10.py` | 애니메이션 |
| `smoke13.py` | 엣지 이름 선 위 스냅 |

브라우저 콘솔과 테스트에서 쓰라고 `window.Orchard` 로 내부를 열어 두었다.

## 그래프 이름

상단 `Orchard` 옆 칸에 이 그래프의 이름을 적을 수 있다. 적어 두면

- 내보내기 파일이 `<이름>.md` / `<이름>.json` 으로 떨어진다
- 마크다운 첫 줄 제목이 그 이름이 된다
- 저장본을 만들 때 기본 이름으로 채워진다
- 브라우저 탭 제목에 뜬다

이름은 그래프와 함께 저장되고 내보내기 JSON 에도 들어가므로, 다른 기기로 옮겨도
따라간다. 파일명에 쓸 수 없는 문자(`/ \ : * ? " < > |`)는 저장할 때 걸러낸다.

## 폰에서 보기

배포 주소를 폰에서 열면 **읽기 전용 뷰어**로 뜹니다. 좁은 화면(≤760px)에서 저절로
켜지고, `보기 → 읽기 전용`으로 직접 켜고 끌 수도 있습니다.

- 두 손가락으로 벌려 확대, 한 손가락으로 화면 밀기
- 노드·라벨 끌기와 편집 도구는 꺼집니다. 한 손가락이 온전히 화면 밀기에 쓰이고
  잘못 눌러 그래프가 바뀔 일도 없습니다
- 사이드 패널은 바닥에서 올라오는 시트로 바뀝니다

### 그래프를 폰으로 넘기기

노트북에서 `폰으로` 버튼을 누르면 QR 과 링크가 나옵니다.

그래프 전체가 주소의 `#` 뒤에 압축되어 들어갑니다. **해시는 서버로 전송되지 않으므로**
어디에도 올리지 않고 기기 사이로만 옮겨집니다. 노드 41개 그래프가 약 2,500자입니다.

QR 과 링크는 같은 그래프를 서로 다른 꼴로 담습니다.

| | 꼴 | 이유 |
|---|---|---|
| 링크 | `#g=z…` base64 | 짧다 |
| QR | `#g=b…` base32 | QR 영숫자 모드에 들어가 모듈이 줄어든다 (165 → 153) |

QR 은 그래프가 커질수록 빽빽해집니다. 150모듈을 넘으면 폰 카메라가 못 읽을 수 있어
안내 문구가 바뀌며, 한 장에 아예 안 들어가면 QR 을 숨기고 링크만 보여줍니다.
**링크는 크기와 무관하게 항상 됩니다.**

링크로 연 그래프는 편집 모드에서 작업본을 덮어쓰기 전에 먼저 묻습니다. 읽어 들인 뒤
주소에서 해시를 지웁니다 — 남겨 두면 새로고침할 때마다 그때 그 그래프로 되돌아갑니다.

## MCP — Claude 채팅으로 그래프 고치기

`mcp/` 에 로컬 MCP 서버가 있다. Claude 데스크톱 앱에 붙이면 채팅으로 키워드를 넣고
연결을 만들고 관련 연구를 붙일 수 있다. 같은 파일을 쓰므로 브라우저가 1~2초 만에 따라온다.

```
Claude 채팅 → MCP 서버 → v1.json → (폴링) → 브라우저
```

### 설치

이 저장소를 받은 PC 마다 한 번씩 해야 한다. GitHub 는 코드를 나를 뿐 설치는 하지 않는다.

```bash
cd ~/Orchard/mcp && npm install
```

**npm install 없이 쓰려면** `mcp/bundle/server.js` 를 가리키면 된다. SDK 까지 한 파일에
넣어 둔 것이라 node 만 있으면 돈다. 다른 PC 에서는 `git pull` → 설정 → 앱 재시작으로 끝난다.
서버 코드를 고쳤으면 `cd mcp && npm run bundle` 로 다시 만든다.

### 그래프 파일은 따로 옮겨야 한다

설치보다 이쪽이 실제 걸림돌이다. 다른 PC 에는 `v1.json` 이 없거나 옛날 것이다.
저장소에 그래프를 넣으면 공개된다는 점을 생각해서 정한다.

| 방법 | 어떻게 |
|---|---|
| 클라우드 폴더 | `v1.json` 을 OneDrive·Drive 안에 두고, 브라우저의 `파일 연결`과 MCP 설정이 그 경로를 보게 한다. 양쪽 PC 에서 같은 파일을 본다 |
| 비공개 저장소 | 그래프만 담는 private 저장소를 따로 만들고 `git pull` 로 맞춘다. 자동은 아니다 |
| 링크로 그때그때 | `폰으로` 버튼의 링크를 다른 PC 브라우저에 붙여넣는다. 옮기기는 되지만 그 PC 의 파일과는 이어지지 않는다 |

둘 다에서 동시에 고치면 클라우드 동기화가 충돌본을 만든다. 한 번에 한 PC 에서 쓰는 전제다.

### Claude 데스크톱에 등록

윈도우의 `%APPDATA%\Claude\claude_desktop_config.json` 에 넣는다.
앱은 윈도우에서 돌고 저장소는 WSL 에 있으므로, WSL 의 node 를 부르는 쪽이 간단하다.

```json
{
  "mcpServers": {
    "orchard": {
      "command": "wsl.exe",
      "args": [
        "node",
        "/home/wsjeon/Orchard/mcp/server.js",
        "/mnt/c/Users/ws/Downloads/Orchard/v1.json"
      ]
    }
  }
}
```

두 경로는 **그 PC 에 맞게 바꾼다** — 앞은 저장소 안의 `mcp/server.js`
(또는 `mcp/bundle/server.js`), 뒤는 그 PC 의 그래프 파일.

윈도우에 node 가 있고 그쪽에서 돌리고 싶으면 `command` 를 `node`, 첫 인자를
`\\wsl$\<배포판>\home\wsjeon\Orchard\mcp\server.js` 로 바꾼다. SDK 는 순수 JS 라
WSL 에서 설치한 node_modules 를 윈도우 node 가 그대로 쓴다.

저장한 뒤 **앱을 창만 닫지 말고 완전히 종료했다가** 다시 연다. 설정은 시작할 때만 읽는다.

### 도구

| 도구 | 하는 일 |
|---|---|
| `get_graph` | 그래프 전체를 읽는다. 무엇을 제안할지 정하려면 먼저 이것부터 |
| `find_gaps` | 관련 연구 없는 키워드, 외톨이 키워드, 이름 없는 그룹·연결 |
| `add_keyword` | 키워드 추가 (`near` 를 주면 그 옆에) |
| `connect` | 키워드 둘 이상을 한 연결로 (셋 이상이면 벤츠 마크) |
| `add_sub` | 하위 키워드 붙이기 — 없는 키워드는 만들어 붙인다 |
| `make_group` | 느슨하게 묶기 |
| `rename` | 이름 바꾸기. 이름 없는 그룹은 멤버를 콤마로 적어 찾는다 |
| `set_note` | 메모 (`append` 로 덧붙이기) |
| `add_works` | 관련 연구 붙이기 |

"추천 키워드 생성"이나 "논문 찾기"는 도구가 아니다 — Claude 가 `get_graph` 로 읽고
웹 검색으로 찾아서 위 도구로 써넣는다. 무엇을 제안할지는 `orchard-graph` 스킬이 맡는다.

### 설계에서 조심한 것

- **도구를 부를 때마다 파일을 다시 읽는다.** 통째로 들고 있다가 쓰면 그 사이
  브라우저에서 고친 것을 덮어쓴다. 테스트로 확인한다
- **임시 파일에 쓰고 바꿔 끼운다.** 브라우저가 1.2초마다 들여다보므로 그냥 덮어쓰면
  반쯤 쓰인 파일을 읽을 수 있다
- **새 키워드를 빈자리에 놓는다.** 좌표를 0,0 으로 두면 전부 한 점에 쌓인다
- **이름이 없거나 여럿이면 분명히 알려 준다.** 엉뚱한 노드에 붙이면 한참 뒤에야 알아챈다
- `seq` 는 파일에 적힌 값과 실제 쓰인 번호 중 큰 쪽을 쓴다 — 낮게 저장돼 있으면 id 가 겹친다

### 테스트

서버를 실제로 띄우고 MCP 프로토콜로 부른다. 파일이 정말 바뀌었는지 매번 직접 읽어 확인한다.

```bash
node mcp/test_server.mjs <그래프파일>
```
